# BUG-005：设置页各区块不随数据变化重渲染——回滚后表单显示回滚前旧值，token 后快照列表仍报 401

- **状态**：VERIFIED（2026-10-26 M2 回归轮）
- **报告人**：QA（T3）
- **报告日期**：2026-10-26
- **严重度**：S2 一般（界面与真实数据不一致，直接误导操作；数据层本身已正确收敛）
- **优先级**：P2
- **归属岗位**：前端（settings 页渲染层未订阅同步/回滚后的状态更新）
- **发现途径**：浏览器 E2E（回归清单 ID：SNAP-09 / AUTH-06 关联观察；亦涉及 D27 已批准 P2 修复项的落实验证）
- **契约依据**：章程 §0（回滚可用性）、D22（同步状态展示）、D27（「回滚成功后自动刷新快照列表与同步状态」，P2 修复批项）

## 复现步骤（现象 A：回滚后表单不刷新，最误导）

1. 设置页创建快照（label「QA回归-回滚前」，此时 settings.spend=6000）。
2. 月支出改为 7777 → 保存（服务端 settings=7777）。
3. 点该快照的「↩️ 回滚」→ confirm 接受。绿色横幅「已回滚到快照 #1，本地已与服务器收敛。」
4. 读月支出输入框显示值、IndexedDB kv.settings、服务端 state。

| | 结果 |
|---|---|
| 期望 | 输入框回显 6000（与 kv/服务端一致） |
| 实际 | 输入框仍显示 **7777**；而 kv.settings={spend:6000, deviceId:"server-restore"}、服务端一致——数据层三步协议收敛正确，仅界面未重渲染。此时用户直接再点「保存月支出」会把 7777 重新写回 |

## 复现步骤（现象 B：token 设置后快照列表陈旧）

1. 全新会话打开设置页（token 未设置）：快照面板显示「快照列表不可用（缺少或错误的 X-Auth-Token…）」。
2. 录入 token → 保存 → 「立即同步」成功（绿色「同步完成」）。
3. 观察快照面板文案。

| | 结果 |
|---|---|
| 期望 | token 生效后快照列表恢复（至少显示「暂无快照」） |
| 实际 | 仍显示 401 错误文案，直到整页刷新 |

## 其他同族表现（同一根因）

- 导入 apply 后「当前分类规则」行仍显示「雇主关键词 [无] · 奖金下限 —」，整页刷新后显示正确值「[示例科技有限公司] · 20000 · 5000」（与 txns.rules 实际生效规则不一致，见 tests/evidence/05、10）。
- 回滚成功后「上次同步」状态行未更新（仍显示回滚前时刻），meta.lastSync 实际已更新——即 D27 已批准的 P2 修复项「回滚后自动刷新快照列表与同步状态」在本轮构建中未见生效（若 P2 修复批尚未执行，此条按计划内待办跟踪）。

## 影响面与初步分析

- 影响面：设置页是「数据操作唯一入口」，回滚/导入/token 变更后的界面陈旧会让用户基于错误显示做出覆盖性写操作（如把 7777 写回）；顺带掩盖真实同步状态。
- QA 初步定位（只报不修）：设置页各区块仅在页面加载时渲染一次，flushOutbox/restore/pullState 完成后未触发对应区块重渲染；横幅提示「本页数据已刷新」与实际渲染状态不符。

## 回归记录

- 修复提交：前端 P2 修复批（设置页面板重建统一由 core `chijia:rendered`/`chijia:pulled` 事件驱动，rerender 广播含快照列表与同步状态，D27）
- 回归测试：2026-10-26 M2 回归轮（QA）——**三现象均 PASS → VERIFIED**
  - 现象 A（回滚后表单回显）：月支出 6000 → 建快照 #1「QA回归-回滚前」→ 改 7777 保存（服务端=7777）→ 回滚 #1（confirm 接受）→ 输入框回显 **6000**（DOM 读值 + 截图），与服务端（deviceId=server-restore, spend=6000）一致；快照列表自动刷新出现「自动快照 · 回滚前」（#2）；「上次同步」状态行更新为回滚时刻（D27 生效）。证据：t03_rollback_banner_snapshot_list_refreshed.png、t04_input_6000_after_rollback.png。
  - 现象 B（token 后快照面板恢复）：全新会话（清站点数据）无 token → 快照面板显示 401 文案（t01 基线）→ 录入 token 保存 →「立即同步」→ **未整页刷新**面板即恢复为「暂无快照：…」（t02/t02b），状态行「token：已设置 ✓ · 上次同步：…」。
  - 现象 C（分类规则行实时）：apply 后规则行即时显示真实值（[示例科技有限公司] · 工资 · 20000 · 5000）；改奖金下限 20000→15000 保存后规则行**立即**更新为 15000，重新解析即时重分类（15000/26000 两笔判奖金、12000 一笔工资，t09），随后恢复 20000。
  - 次要观察（不阻塞销单）：③ 区顶部「月支出口径已保存：7,777.00 元/月。」是回滚前保存动作的历史反馈横幅，回滚后未清除；其性质是动作回执而非数据显示，输入框与数据层均已一致。
