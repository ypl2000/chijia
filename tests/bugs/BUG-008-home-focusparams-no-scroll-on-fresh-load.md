# BUG-008：首页「🎛 去调参数」首次直达时参数面板滚动不到位（面板已展开但停留在视口外）

- **状态**：OPEN
- **报告人**：QA（T5-A 复检轮 R4）
- **报告日期**：2026-11-03
- **严重度**：S3 轻微（直达路径承诺未兑现；面板已展开，手动滚动即见，无数据风险）
- **优先级**：P2
- **归属岗位**：前端
- **发现途径**：浏览器 E2E（回归清单 ID：A-03；关联 UX-SPEC 流程②、D16）
- **契约依据**：docs/UX-SPEC.md §2 流程②「参数面板自动展开并滚动到位」；首页直达入口面板自身文案「计划页参数面板（自动展开并滚动到位）」

## 复现步骤

1. （环境：`python backend/app.py --port 8411`，token 见 backend/data/token.txt）
2. 打开 http://127.0.0.1:8411/ 首页；确保计划页 iframe 尚未加载过（首次会话或刷新后直接操作）。
3. 点击首页「🎛 去调参数」直达按钮。
4. 观察计划页：④参数面板 `open=true`（已展开），但页面滚动位置停在页首附近（iframe scrollY≈79），面板 top≈997px，远在视口（高 720/844px）之外。

## 期望 vs 实际

| | 结果 |
|---|---|
| 期望（UX-SPEC 流程② / D16） | 切到计划 Tab 后参数面板**自动展开并滚动到位**（`plan.html#params` 直开路径 M2 轮已验证滚动到位 top≈92） |
| 实际 | 面板展开 ✓，但**未滚动到位**：scrollY 稳定停在 79，panelTop≈997，等待 3.2 秒（8 次采样）无后续滚动；仅当 iframe 已加载过（二次调用 `__chijia.focusParams()`）时滚动才生效（scrollY 0→1076、panelTop=0） |

## 证据

- 截图：tests/evidence/r4/t11_bug008_params_not_in_view.png（直达后计划页停在页首，参数面板不在视野内）
- 页面时序采样（首次直达路径，间隔 400ms）：scrollY 恒为 79、panelTop 恒为 997（t=400ms…3200ms 共 8 次采样无变化）
- 对照实验：对已加载 iframe 手动调用 `window.__chijia.focusParams()` → scrollY=1076、panelTop=0（钩子本身逻辑正确）
- 可疑方向（只报不修）：壳 `activate()` 在 iframe `load` 事件后立刻执行钩子，此时计划页自身 boot/异步渲染尚未完成，布局随后变化把面板推回视口外，smooth 滚动被中断/失效；plan.html:144-150 的 focusParams 与 index.html:140-157 的 activate 时序

## 影响面与初步分析

- 影响：首页「🎛 去调参数」直达路径（UX-SPEC 三条关键任务流之一）；`plan.html#params` hash 直开路径不受影响（M2 轮 PLAN-04 已验证）
- 违背 UX-SPEC §2 流程②硬性要求（「违背本规范 = 验收不通过」），但功能可用（面板已展开），不阻塞数据与同步
- 关联测试：tests/功能检测清单.md A-03
