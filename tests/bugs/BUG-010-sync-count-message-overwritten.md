# BUG-010：「立即同步」的计数结果「推送 X 项…拉取应用 Y 项」被通用文案瞬时覆盖，用户不可见

- **状态**：OPEN
- **报告人**：QA（T5-A 复检轮 R4）
- **报告日期**：2026-11-03
- **严重度**：S3 轻微（同步本身成功且有绿色完成提示；仅计数明细对用户不可见）
- **优先级**：P3
- **归属岗位**：前端
- **发现途径**：浏览器 E2E（回归清单 ID：F-14、G-02/G-03 同步提示）
- **契约依据**：清单 F-14 期望「绿色『同步完成：推送 X 项…拉取应用 Y 项』」

## 复现步骤

1. （环境：`python backend/app.py --port 8411`，token 已设置；第二设备对任一实体做一次较新写入，如 settings.spend）
2. 设置页 ④ 同步与连接 → 点「🔄 立即同步」。
3. 观察状态行（以 30ms 间隔轮询采样 2.5 秒）。

## 期望 vs 实际

| | 结果 |
|---|---|
| 期望（清单 F-14） | 状态行稳定显示「同步完成：推送 X 项（服务端较新覆盖 Y），拉取应用 Z 项。」 |
| 实际 | 该计数文案**从未被观测到**（30ms 轮询全窗口仅捕获「同步中…」→「同步完成，本页数据已刷新。」两条）；代码里 `statusIn(ok, "同步完成：推送…拉取应用…")`（settings.html:571）在下一行立即被 `await afterDataChange(mount, "同步完成，本页数据已刷新。")`（settings.html:572）的通用文案覆盖 |

## 证据

- 截图：tests/evidence/r4/t17_g02_pull_7000_noreload.png（同步完成后稳定显示的是通用文案「同步完成，本页数据已刷新。」；当时实际「拉取应用 1 项」——settings.spend 由 6200 更新为 7000）
- 轮询采样（G-02 场景，点击后 2.5s 内每 30ms 读取状态行）：`["同步中…", "同步完成，本页数据已刷新。"]`，无计数文案
- 代码观察（只报不修）：settings.html:571-572 两条 statusIn 连续执行，后者无条件覆盖前者

## 影响面与初步分析

- 同步功能与数据收敛不受影响（G-01~G-08 全部通过）；仅「推送/拉取计数」这一反馈细节失效，F-14 的期望文案无法达成
- 初步定位：`afterDataChange` 的通用提示与同步计数提示写同一状态行，二选一即可（如保留计数、把「本页数据已刷新」并入同一条文案）
