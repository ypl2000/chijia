# BUG-009：设置页「清除」token 后快照面板仍显示旧列表（不即时切换为「不可用」提示）

- **状态**：OPEN
- **报告人**：QA（T5-A 复检轮 R4）
- **报告日期**：2026-11-03
- **严重度**：S3 轻微（状态显示不同步；回滚点击后会以 alert 优雅失败，无数据风险）
- **优先级**：P3
- **归属岗位**：前端
- **发现途径**：浏览器 E2E（回归清单 ID：F-13）
- **契约依据**：清单 F-13 期望「快照面板变为『不可用（缺少或错误的…token…）』类提示，不白屏」

## 复现步骤

1. （环境：`python backend/app.py --port 8411`，token 见 backend/data/token.txt；快照列表已有若干条目）
2. 设置页 ④ 同步与连接 → 点「清除」→ 状态行变「token 已清除。」、信息行变「token：未设置（/api/* 将 401）」。
3. 观察同页「快照管理」面板。

## 期望 vs 实际

| | 结果 |
|---|---|
| 期望（清单 F-13） | 快照面板变为「不可用（缺少或错误的…token…）」类提示（GET /api/snapshots 将 401，面板应反映当前不可用状态） |
| 实际 | 清除后快照列表**原样滞留**（6 行快照与「↩️ 回滚」按钮全部保留，可继续点击但必然失败）；「快照列表不可用…」提示**不出现**；仅当页面重建（刷新/事件重建面板）后 `refreshSnapshots()` 重新拉取才显示不可用提示 |

## 证据

- 截图：tests/evidence/r4/t20_bug009_snaplist_stale_after_clear.png（tokenInfo 已显示「未设置」，快照列表 6 条照旧）
- 代码观察（只报不修）：settings.html `btnClear` handler（≈L561-565）只调 `setAuthToken('')+refreshInfo()+statusIn`，不调 `refreshSnapshots()`；`refreshSnapshots()` 仅在面板构建时与回滚成功后触发（settings.html:201/241）
- 对照：页面重建后（无 token）面板正确显示「快照列表不可用（缺少或错误的 X-Auth-Token…）后端未启动或 token 未设置时不影响本机使用。」——降级文案本身存在且正确，问题仅在「清除」动作不触发刷新
- 影响面：仅设置页快照面板状态显示；点击滞留列表中的「回滚」会走 alert 优雅失败（数据不损），不违反 H-01/H-04 红线

## 影响面与初步分析

- 轻微 UX 一致性问题：token 失效后用户看到的是「可用」的快照列表，与实际权限状态不符
- 初步定位：btnClear 缺一次 `refreshSnapshots()`（或快照面板订阅 token 变更事件），属前端装配遗漏，非协议/数据问题
